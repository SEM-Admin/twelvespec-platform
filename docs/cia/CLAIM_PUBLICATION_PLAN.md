# Evidence-backed website capability claims

Baseline: main `14f30e2`, merged PRs #4 and #5. The latter passed 323 backend tests and 23 browser journeys in [CI](https://github.com/SEM-Admin/twelvespec-platform/actions/runs/43332200930). Architecture PR #3 remains a draft at `5a07a1c`; its consolidated handoff and three CIA contracts govern this additive implementation. No deployment or real-account activation is included.

## Compatibility and scope

Marketing already owns Website Studio, immutable content revisions, site-scoped editorial permissions, explicit publisher approvals, release manifests, schedules and rollback. Intelligence owns immutable evidence sources and append-only revocations. Reuse both. Do not create a competing claims CMS, approval engine, product identity, source registry or publication pipeline.

Add an optional **capability claims** page section. Each assertion has its own ID, statement, context, public limitations, controlled capability and delivery model, service/territory/website scope, truth status, evidence confidence, authoring origin, verification/effective/expiry dates, private supporting sources and review reference. The existing exact-revision approval records the actual human publisher and time. Persist citation edges in existing immutable `content_references`.

This slice covers service/workflow capabilities. Product/variant stock, firm prices, lead-time promises, engineering signoff and manufacturing release remain with their existing owners and gates. Product-specific assertions are not accepted by this section's schema. Advanced engines remain unavailable, with explicit Coming Soon presentation only. Neither a source nor a publisher approval activates them.

Introduce an explicit `PUBLIC_CLAIM` permitted use on evidence sources. Existing internal/quote permissions do not imply this permission and existing immutable sources are not upgraded. A steward must register a new source edition when its granted uses change. Synthetic sources cannot support published assertions. Permission and human review are recorded assertions, not independent legal or factual certification.

The public projection contains only the approved statement, context, limitations, scope and truthful availability/delivery labels. It must not serialize source IDs, source URIs, publishers, rights references, private review references, fingerprints, author identities or wholesale economics. Anonymous readers get a narrow eligibility result for a claim in a visible active release, never access to the evidence tables or an arbitrary-source lookup.

## Implementation constraints

- Drafts may contain unverified, retired or incomplete claims. Publication of visible claims requires all mandatory fields and current, explicitly permitted, non-synthetic evidence. Hidden entries are never projected publicly.
- Controlled available service/workflow definitions describe verified application behavior or human-managed sourcing; they do not certify equipment ownership, fulfillment capacity or manufacturer acceptance. Human review must verify the precise statement and territorial scope against its sources.
- `PLANNED_NOT_AVAILABLE` must render as Coming Soon; `UNVERIFIED_DO_NOT_PUBLISH` and `RETIRED` must not publish. AI-assisted assertions require the same source and human approval gates; model confidence is never proof.
- Source revocations share Intelligence's existing transaction lock with publication checks. Public reads observe one database snapshot; loaded browser pages are not retroactively erased. Public requests remain uncached. Revalidation does not silently change the approved release manifest.
- A narrowly scoped, fixed-search-path SQL function may inspect private sources only to return eligibility for a visible active-revision claim. Revoke default PUBLIC execution; no public raw table grants. The private editor picker exposes only the minimum source-selection fields after existing site EDIT authorization.
- Claim authoring and private evidence are internal Marketing responsibilities. Store-admin site editing does not grant evidence access: the database withholds claim-bearing revisions (including hidden sections/history) and citation edges from that role. Ordinary pages and authorized public projections remain usable. An internal editor manages a page containing private claim evidence; this is not a new supplier permission for store admins.
- All test fixtures are isolated local/synthetic business scenarios. A test source marked `OPERATOR_DOCUMENT` tests that branch of the policy; it does not establish any real TwelveSpec service claim.
- Existing narrative, SEO and arbitrary rich text are **not semantically verified** by this typed section. Coverage of legacy/free-text claims, product-specific assertions, non-website channels and the full original CMS acceptance inventory remains OPEN. Do not label the entire customer-trust contract complete.

## Release and reversal

Use an additive migration. Existing sources, content, approvals and releases keep their identities and meaning. No initial capability assertion is auto-published. An older application can continue to serve older releases. A database reader protocol guard withholds new claim-bearing page revisions from older readers that cannot strip their private metadata. Restore a compatible, currently valid release before rolling the application back; the guard prevents disclosure but cannot preserve a new page's availability under old code. Normal rollback still revalidates current rights. Do not delete audit history or downgrade schema as an application rollback.

## Necessary recovery compatibility correction

The first full regression exposed a real omission in `packages/kernel/src/backup.ts`: its generic operational-row table list excluded the seven CIA ledgers and five supplier API metering/cache/credential tables. New claim citation foreign keys made that omission fail the restore drill. The local-only drill now discovers all 114 application tables without widening the generic API inventory, restores their scoped foreign keys, decodes only typed PostgreSQL bytea columns, preserves timestamp precision and verifies database-native content hashes as well as counts/scopes. Buffer-shaped JSONB stays JSON. `tests/integration/recovery.test.ts` creates its own synthetic cited draft, precise price, binary and mock supplier charge/cache/ciphertext fixtures, so the regression does not depend on test ordering. The supplier dispatch is simulated and costs nothing. This remains a local database recovery test; durable original files, managed backups, usable vault-key recovery and a hosted production restore are not verified.
