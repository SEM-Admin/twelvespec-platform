## Verified architecture and decision

Keep the two Next.js interfaces (`apps/shop`, `apps/os`), shared TypeScript services, PostgreSQL scope/foreign keys, Better Auth memberships, one transactional outbox and `apps/worker`. CIA is a shared evidence and decision capability, not a third application, a second catalog, or a new transaction engine. PostgreSQL is sufficient for the first slices. No graph database, embeddings, paid model, Python/Rust service, GPU, Redis or new queue is justified by measured need yet.

`packages/kernel/src/index.ts` supplies `Actor`, `Tx`, `Row`, `transaction`, `authorize`, `event`, `idempotent`, and explicit table allowlists. `transaction` checks membership, enters `ts_runtime`, and sets tenant/workspace/user/role settings. `app.scope_ok` and forced RLS enforce scope. Migrations 001–010 are the current schema; domain records commonly use typed scope/FK columns plus JSON data. This is not an already normalized PLM ontology.

The current public repository must contain synthetic fixtures and public research only. Private account agreements, supplier prices, credentials, customer records and restricted catalogs belong in scoped runtime storage. New CIA data must never be added to the generic customer table list, public catalog/quote projections, search documents or event payloads by default.

Fresh baseline, local isolated PostgreSQL: `npm test` passed **251 tests / 36 files** on November 12. The first attempt found the local database stopped (`ECONNREFUSED 127.0.0.1:55432`); starting the existing local database resolved it. This does not verify Supabase or any supplier. The earlier 18-browser-journey CI result is historical until this branch reruns it. Hosted previews are not upgraded by a GitHub commit.

## First recommended milestone and dependencies

**M1: precise, private, immutable price evidence that the existing Sales/estimating boundary can assess without issuing a quote.** Implement source manifest + append-only rights restriction + exact product/variant price observations, preserving raw values and 2025/2026 editions. Store a versioned assessment against a draft quote line. Separate published facts from authorized current net; return explicit exclusions and unknowns. Extend unit/pack value before currency rounding in the existing pricing package. Do not automatically promote observations to supplier offers, public listings, issued terms, purchases or production readiness.

This is smaller and safer than simultaneously introducing a full PLM schema, universal graph, AI service or manufacturing engine. It provides an executable cross-domain join (supplier provenance → catalog identity → pricing → Sales assessment), not a disconnected research archive. M1 is not the full 48-cap qualifier.

1. **M1 (this implementation branch):** precise evidence and draft-line financial assessment. Synthetic tests; no networking/deployment/service cost. Operator records a manifest and observation, assesses a selected line, reviews reasons. No paid API query per customer page view.
2. **M2:** 48 embroidered caps qualification through existing RFQ/quote workspace, plus exact designer rebind/proof fixes. Link blank + decorator + setup/prepress/packaging/freight, availability and delivery/artwork evidence; unknowns block complete recommendation. Store decision/evidence/rule versions. No auto-issue or production release. UI and full requirement/route qualification are dependencies, not claimed by M1.
3. **M3:** production-owned immutable process profile, product-definition revision/thread and method interpretation links. Explicit product/variant/substrate/zone/producer/facility applicability. Legacy design adapter; no retrofit approval of old artwork. Four proof/prototype pilots: cap, sticker/cut path, brochure, original retail requirements/components/BOM/spec draft. Each remains blocked where producer evidence/qualified review is missing.
4. **M4:** one genuinely accepted method adapter at a time; qualified profiles, scan/storage, hash manifest, attributable human release and external/physical acceptance. CAD/3D remain references until separately validated. Engine/license/manufacturer dependencies below.
5. **M5:** whole-dataset actual outcomes and safe event integration; reconcile touch time, costs, QC, delivery and remakes before claiming improvement. This also repairs V1 reporting/event gaps.

Existing V1 durability, source eligibility, store/kit identity, supplier protocols and release gates continue alongside these slices. No requirement silently disappears. [M1 traceability and implementation design](FOUNDATION_DESIGN.md) distinguish proposed tests from passing evidence.
